# Taste Report Product Context

## 1. 제품 정의

Taste Report는 영화와 음악에 관한 짧은 질문을 통해 사용자의 실제 선택을 수집하고, 질문의 맥락과 콘텐츠 정보를 교차 분석해 취향을 하나의 재미있는 콘텐츠로 만들어 주는 서비스다.

핵심 경험:

```text
질문 → 콘텐츠 선택 → 의미 보존 → 공개 정보 조사 → AI 해석 → 캐릭터화 → 추천 → 공유
```

핵심 문장:

> 영화와 음악에 답하다 보면, AI가 내 취향을 알아보고 하나의 캐릭터로 만들어준다.

## 2. 사용자 가치

- 무엇을 좋아하는지 쉽게 떠올릴 수 있는 질문형 입력
- 선택한 작품과 답변을 알아봐 주는 구체적인 해석
- 공통점뿐 아니라 상황별 차이와 의외성의 발견
- 캐릭터·한줄평·성적표를 통한 재미있는 자기표현
- 취향과 연결되는 이유가 있는 새로운 콘텐츠 추천
- 친구나 SNS에 공유하기 쉬운 결과 이미지

주요 대상은 영화·음악 소비를 즐기고, 가벼운 테스트와 AI 해석 및 결과 공유에 관심이 있는 10~30대 사용자다.

## 3. MVP 범위

### 포함

- 영화 테마 우선 구현
- 테마별 질문지와 콘텐츠 검색·선택
- 질문 역할을 보존한 답변 확인
- 공개 정보 조사와 AI 분석
- 취향 캐릭터, 키워드, 한줄평, 성적표, 근거 있는 총평
- 추천 콘텐츠 3개
- 브라우저에서 생성하는 9:16 공유 이미지
- 영화 MVP 검증 후 음악 테마 추가

### 제외

- 회원가입과 계정
- 사용자 취향 이력 및 분석 결과의 영구 저장
- 저장된 결과를 다시 여는 고유 URL
- 자체 대규모 콘텐츠 데이터베이스
- 드라마·연예인 테마
- 영화와 음악을 합친 종합 취향 프로필
- 전문적인 심리 진단이나 능력 평가

## 4. 영화 질문의 역할

영화 질문은 단순 선호 목록이 아니라 작품과 맺는 관계, 취향의 경계, 추천 의도를 수집한다.

| 역할 | 수집 내용 | 해석 시 주의 |
|---|---|---|
| 선호 장르 | 제한 없이 고른 장르 | 자기보고와 실제 선택의 차이도 관찰 |
| 인생 영화 | 가장 아끼는 영화 1편 | 선택 입력 설명을 최우선 근거로 사용 |
| 최근 만족작 | 최근 본 영화 중 만족한 작품 | 최근 개봉작일 필요 없음 |
| 장르 밖 의외작 | 평소 취향 밖인데 좋았던 작품 | 취향 확장의 근거 |
| 기대와 달랐던 작품 | 명작·추천작 중 맞지 않은 작품 | 입력하지 않은 불호 이유를 추정하지 않음 |
| 최애 캐릭터 | 영화와 캐릭터 | 해당 영화 전체를 좋아한다고 간주하지 않음 |
| 기억나는 대사 | 영화와 사용자의 기억 | 공식 인용으로 표시하지 않음 |
| 친구 추천작 | 힘든 친구에게 건넬 작품과 마음 | 개인 최애와 같은 의미로 처리하지 않음 |
| 추가 긍정 작품 | 아직 나오지 않은 선호작 최대 5편 | 긍정 선호 표본 보완 |

동일한 영화가 여러 질문에 등장할 수 있다. 분석에서는 작품 수를 중복 제거하지만 등장한 모든 역할을 보존한다.

### 영화 질문지 화면 사양

Notion의 `영화 질문지`를 원본 기획으로 삼고, 화면 문구는 자연스러운 존댓말로 통일한다. 한 화면에는 질문 하나만 표시하며 아래 순서를 바꾸지 않는다. 장르는 복수 선택을 허용하고, 작품 선택 질문은 마지막 추가 작품을 제외하면 한 작품만 받는다. 질문 위에 별도의 감성 문구나 설명 문구는 두지 않는다.

| 순서 | `question_id` | 분석 역할 | 사용자에게 보여줄 질문 | 입력 |
|---|---|---|---|---|
| 1 | `movie_primary_genre` | `self_reported_genre` | 평소 좋아하는 영화 장르를 모두 골라주세요. | 장르 복수 선택, 제한 없음 |
| 2 | `movie_life_movie` | `core_positive_preference` | “이건 내 인생 영화다” 싶은 한 편은 뭐예요? | 영화 1편 |
| 2-1 | `movie_life_movie_pitch` | `user_expression` | 이 영화가 내 인생 영화가 된 가장 큰 이유는 뭐예요? | 선택 서술, 100자 |
| 3 | `movie_recent_favorite` | `recent_positive_preference` | 올해 본 영화 중 가장 재미있었던 한 편은 뭐예요? | 영화 1편 |
| 4 | `movie_outside_taste` | `taste_expansion` | 앞에서 고른 장르에는 속하지 않지만, 가장 재미있었던 영화는 뭐예요? | 선택 장르를 문구에 반영, 영화 1편 또는 없음 |
| 5 | `movie_not_for_me` | `negative_boundary` | 다들 재미있다고 했는데, 나만 별로였던 영화가 있나요? | 영화 1편 또는 없음 |
| 6 | `movie_favorite_character` | `character_attachment` | 영화 속 캐릭터 중 유독 마음이 가는 최애는 누구예요? | 영화 1편과 캐릭터명 또는 없음 |
| 7 | `movie_memorable_quote` | `memory_fragment` | 영화가 끝난 뒤에도 계속 떠오른 대사가 있나요? | 영화 1편과 기억한 문장 또는 없음 |
| 8 | `movie_friend_recommendation` | `social_recommendation` | 힘든 하루를 보낸 친구에게 영화 한 편을 건넨다면? | 영화 1편 |
| 8-1 | `movie_friend_intention` | `recommendation_intent` | 그 영화를 추천한 이유나, 함께 전하고 싶은 마음은 뭐예요? | 선택 서술, 180자 |
| 9 | `movie_additional_favorites` | `additional_positive_preference` | 아직 말하지 못한 내 취향 영화들을 꺼내볼까요? | 영화 0~5편 |

영화 장르 보기는 `드라마 / 코미디 / 로맨스 / 액션 / 스릴러·미스터리 / 범죄 / SF / 판타지 / 공포 / 애니메이션 / 다큐멘터리 / 기타 · 좋아하는 장르가 여기에 없어요`로 시작한다. 선택 개수에는 제한을 두지 않고, 기타를 고른 경우 사용자가 직접 장르를 적을 수 있다.

친구 추천 이유는 객관식으로 축약하지 않고 사용자의 문장으로 받되 건너뛸 수 있다. 친구의 구체적인 사연이나 개인정보는 요구하지 않는다. 영화 질문지의 모든 주관식 입력은 선택 사항이며, 작성하지 않아도 다음 질문으로 진행할 수 있다.

## 5. 음악 질문의 역할

음악 질문은 깊은 개인사를 강요하지 않고 현재의 청취 습관과 상황별 선곡을 수집한다.

| 역할 | 수집 내용 | 해석 시 주의 |
|---|---|---|
| 선호 장르·가수 | 장르 최대 3개, 가수 최대 3팀 | 자기보고 단서 |
| 청취 상황·중요 요소 | 상황·요소 각각 최대 3개 | 사용자가 직접 밝힌 기준 |
| 최근 반복곡 | 요즘 많이 듣는 TOP 3 | 핵심 긍정 선호 |
| 마지막 청취곡 | 가장 마지막 곡 | 우연 가능성이 있어 낮은 가중치 |
| 차 안 첫 곡 | 함께 이동할 때의 선곡 | 사회적·활기 맥락 |
| 공부곡 | 집중 상황의 선곡 또는 해당 없음 | 음악을 듣지 않는 답도 유효 |
| 퇴근곡 | 하루를 끝내는 상황의 선곡 | 회복·전환 맥락 |
| 추가 추천곡 | 다른 사람에게 보여줄 곡 최대 5개 | 긍정 선호 보완 |

상황별 선곡을 개인 최애와 동일하게 취급하지 않는다. 음악 지식이나 수준을 평가하지 않는다.

### 음악 질문지 화면 사양

Notion의 `노래 질문지`를 원본 기획으로 삼는다. 영화와 마찬가지로 한 화면에 질문 하나, 마지막 추가 추천곡을 제외하면 답 하나를 원칙으로 한다.

| 순서 | `question_id` | 분석 역할 | 사용자에게 보여줄 질문 | 입력 |
|---|---|---|---|---|
| 1 | `music_primary_genre` | `self_reported_genre` | 내 플레이리스트에서 가장 자주 만나는 장르는 뭐예요? | 장르 1개 |
| 2 | `music_favorite_artist` | `favorite_artist` | 딱 한 팀만 먼저 자랑한다면, 가장 좋아하는 가수는 누구예요? | 가수 1팀 |
| 3 | `music_primary_context` | `listening_context` | 음악이 가장 자주 필요한 순간은 언제예요? | 상황 1개 |
| 4 | `music_decisive_element` | `listening_priority` | 노래에 마음을 뺏길 때, 결정적인 한 방은 뭐예요? | 요소 1개 |
| 5 | `music_recent_repeat` | `recent_core_preference` | 요즘 나도 모르게 계속 재생하는 한 곡은? | 곡 1개 |
| 6 | `music_last_played` | `weak_recent_signal` | 바로 직전에 들은 노래, 기억나나요? | 곡 1개 또는 기억 안 남 |
| 7 | `music_drive_first_song` | `social_context_choice` | 친구들과 놀러 가는 차 안, 첫 곡으로 뭘 틀까요? | 곡 1개 |
| 8 | `music_study_song` | `focus_context_choice` | 집중해야 할 때, 가장 먼저 찾는 한 곡은? | 곡 1개, 음악 안 들음, 정한 곡 없음 |
| 9 | `music_way_home_song` | `transition_context_choice` | 오늘 일정 끝! 집에 가는 길에 틀고 싶은 한 곡은? | 곡 1개 |
| 10 | `music_additional_favorites` | `additional_positive_preference` | 마지막은 자유 선곡! 아직 못 보여준 노래들을 추천해 주세요. | 곡 0~5개 |

음악 장르 보기는 `K-pop / 발라드 / 팝 / 힙합·랩 / R&B·소울 / 록 / 댄스·일렉트로닉 / 재즈 / 클래식 / 포크·어쿠스틱 / 트로트 / 장르를 잘 모르겠어요`로 시작한다.

청취 상황 보기는 `이동할 때 / 공부·작업할 때 / 운동할 때 / 집안일 할 때 / 혼자 쉴 때 / 잠들기 전 / 친구들과 있을 때 / 음악에만 집중할 때 / 그때그때 달라요` 중 하나다. 중요 요소는 `가사 / 목소리·음색 / 멜로디 / 비트·리듬 / 악기·사운드 / 전체적인 분위기 / 유행·화제성 / 익숙함 / 그냥 좋으면 들어요` 중 하나다. `장르를 잘 모르겠어요`, `그때그때 달라요`, `그냥 좋으면 들어요`는 각각 독립적인 단일 답변으로 저장한다.

질문 아래 안내 문구는 순서대로 다음을 사용한다.

1. 요즘의 나와 가장 가까운 장르 하나만 골라주세요.
2. 솔로, 그룹, 밴드 모두 좋아요. 지금 가장 먼저 떠오른 한 팀이면 돼요.
3. 하루 중 음악을 가장 자주 찾는 순간 하나를 떠올려 주세요.
4. 장르보다도 “이게 좋으면 듣는다” 싶은 기준 하나를 골라주세요.
5. 최신곡이 아니어도 괜찮아요. 요즘 가장 자주 돌아가는 한 곡이면 돼요.
6. 자동 재생이나 다른 사람이 튼 곡이어도 괜찮아요. 기억이 안 나면 그렇게 답해 주세요.
7. 오늘 차 안의 DJ는 나예요. 다 같이 듣고 싶은 첫 곡을 골라주세요.
8. 음악을 듣지 않거나 정해 둔 곡이 없다면 그것도 정확한 답이에요.
9. 퇴근이 아니어도 좋아요. 수업이나 하루 일정을 마친 순간을 떠올려 주세요.
10. 예전에 푹 빠졌던 곡이나 오래 아껴 온 곡을 최대 5개까지 골라주세요. 비워도 괜찮아요.

## 6. 분석 원칙

1. 질문의 역할과 사용자 직접 입력을 콘텐츠 정보와 함께 전달한다.
2. 사용자 표현은 외부 작품 정보보다 우선한다.
3. 주요 해석은 어떤 답변에서 나온 것인지 설명할 수 있어야 한다.
4. 입력하지 않은 불호 이유, 성격, 개인적 동기를 단정하지 않는다.
5. 이번 답변 표본에서 나타난 경향임을 전제로 한다.
6. 근거가 부족한 지표는 축소하거나 생략한다.
7. 같은 콘텐츠의 반복 선택은 애착 단서로 사용할 수 있지만 서로 다른 여러 작품처럼 계산하지 않는다.
8. 추천 콘텐츠는 실재 여부와 관련성을 확인하고 이미 선택한 작품을 제외한다.
9. 취향 차이를 모순으로 몰지 않고 상황에 따른 변화로 설명할 수 있다.
10. 대중성·다양성·일관성 같은 점수는 고정 기준에 따른 재미용 AI 추정값임을 표시한다.

- 최근 취향과 본진 취향의 관계
- 선곡 본능 분석과 음악 취향 판독문
- AI가 이미 좋아할 것으로 예측한 곡 3개
- 플레이리스트가 고른 재미용 이상형

## 8. 제품 언어와 안전선

- 친구와 편하게 이야기하는 듯한 자연스러운 존댓말을 사용한다. 억지스러운 반말이나 과도한 유행어는 피한다.
- 사용자의 선택을 조롱하거나 우열로 평가하지 않는다.
- ‘홍대병’, ‘음악력’ 같은 표현은 유머 장치일 뿐 객관적 수준을 뜻하지 않는다.
- 캐릭터는 실제 성격 유형이 아니라 이번 답변에서 드러난 취향을 표현한다.
- 정확한 진단보다 재미·구체성·공유 욕구를 우선하되 사실을 꾸며내지 않는다.

## 9. 성공 가설

- 질문형 입력이 자유 목록보다 완주하기 쉽다.
- 사용자는 자기 답변을 구체적으로 알아봐 주는 해석을 좋아한다.
- 캐릭터와 한줄평은 저장·공유 행동을 유도한다.
- 한 테마의 결과가 다른 테마 참여로 이어진다.
- 이유가 연결된 추천이 결과의 실용성을 높인다.
- 분석 1회 비용과 대기시간을 무료 경험 범위에서 관리할 수 있다.

## 2026-10-09 — 광고 사용 가능한 영화 검색으로 전환

### 결과

- 영화 공급자를 상업·광고 서비스에서 제약이 큰 TMDB 대신 CC0 구조화 데이터인 Wikidata로 전환했다.
- 한국어·영어 검색 후보를 합친 뒤 SPARQL로 영화만 필터링하고, 정확한 제목·원제·연도·감독·제작국과 한글 검색의 한국 영화 우선순위를 반영했다.
- Wikimedia Commons에서 이미지 파일의 저작자·라이선스·원문 링크를 함께 확인하고, 크레딧 가능한 이미지만 결과와 선택 카드에 표시했다.
- 영화 검색 결과를 5분간 캐시하고 Wikimedia 접근 정책에 맞는 `User-Agent`, 타임아웃, 제한 재시도와 오류 매핑을 적용했다.
- 영화 세션 키를 v3로 올려 기존 TMDB 선택 데이터와 새 Wikidata QID가 섞이지 않게 했다.
- API·아키텍처·상태·README를 현재 구현과 배포 주의사항에 맞게 갱신했다.

### 검증

- 백엔드 pytest 6개와 Ruff 통과
- 프론트 `pnpm typecheck` 통과
- 백엔드와 Vite 프록시에서 `괴물`, `기생충`, `Interstellar` 실제 검색 확인
- 인앱 브라우저에서 한국 영화 우선 정렬, 카드 이미지 크롭, 선택 상태와 이미지별 크레딧 링크 확인
- Commons 이미지는 작품별 가용성과 파일 라이선스에 따라 누락되거나 공식 포스터가 아닌 사진일 수 있음을 UI·문서에 명시

## 2026-10-09 — 무료 영화·음악 카탈로그 검색 연동

### 결과

- 영화는 비상업 개발에 무료인 TMDB, 음악은 인증키가 필요 없는 Apple iTunes Search API를 공급자로 확정했다.
- FastAPI에 공급자별 어댑터와 공통 카탈로그 응답 스키마, 영화·음악 검색 라우트를 추가했다.
- TMDB 읽기 토큰은 백엔드 환경 변수에서만 읽고, 타임아웃·제한 재시도·요청 제한·공급자 장애를 사용자용 오류로 매핑했다.
- 음악은 실제 검색에서 KR 스토어가 주요 한국 가수도 빈 결과를 반환해 한국어·영어 검색이 확인된 US 스토어를 사용하고 동일 요청을 60초간 캐시했다.
- 프론트의 로컬 샘플 목록을 실제 `/api/catalog` 호출로 교체하고 350ms 디바운스, 이전 요청 취소, 로딩·빈 결과·오류·재시도와 출처 표기를 구현했다.
- Apple 홍보 자산 조건에 불필요하게 묶이지 않도록 앨범 이미지와 미리듣기는 사용하지 않았다.
- 기존 샘플 선택이 세션에 남지 않도록 영화·음악 초안 저장 키를 v2로 올렸다.

### 검증

- 프론트 `pnpm typecheck`, `pnpm build` 통과
- 백엔드 pytest 5개와 Ruff 통과
- 백엔드 `/api/health`와 Vite `/api/health` 프록시 응답 확인
- Apple 음악 검색은 실제 백엔드·Vite 프록시·인앱 브라우저에서 한국어 가수와 곡 결과를 확인
- TMDB 토큰이 없는 환경에서는 `503 CATALOG_NOT_CONFIGURED`와 프론트 재시도 화면을 확인
- 실제 TMDB 영화 결과 검증과 공식 로고 자산 반영은 토큰 설정 및 공개 배포 전에 남은 작업
